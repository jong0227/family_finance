# 디자인 시스템 — family_finance

> 이 문서는 "무엇을 어떤 색·크기·모양으로 그리는가"의 기준이다. 화면 구조와 데이터는 다른 설계 문서가 맡는다.
> 같은 가족의 `family_timetable`(시간표 앱)에서 **토큰 이름·파일 배치·"색은 정보다" 원칙·폭 구간**을 이어받고,
> 값과 컴포넌트는 돈 앱에 맞게 새로 정했다.
> 구독 관리 앱 **Ninedogs**가 이 앱에 합쳐진다. 사용자가 이미 익숙한 Ninedogs의 서비스 아이콘 처리·분야 색 고정·
> 스포티파이식 온보딩·"목차 칩"은 그대로 이어받고, 색과 글자만 이 문서의 언어로 맞춘다(10장).
> 공개 저장소다. 이 문서의 금액·카드명·통장명은 모두 **가짜 예시**다.

---

## 0. 한 줄 요약

**흰 카드 + 무채색 잉크 + 뜻이 있는 색 세 종류(초과·여유·분류).** 숫자가 주인공이고, 숫자는 늘 그 안의 구성 항목과 함께 나온다.
글자는 작고 촘촘하게(본문 13), 행 구분은 옅은 선 하나, 화면 위쪽 큰 헤더는 없다.

## 1. 트렌드 조사 (2025~2026) — 가져올 것 / 버릴 것

조사 범위: Toss(TDS·토스 프로덕트 산스), Monarch Money, Copilot Money, YNAB, Revolut 10, 뱅크샐러드, 핀테크 UX 트렌드 글·Dribbble류 대시보드.
트렌드 글 상당수는 에이전시 블로그라 **방향 참고**로만 쓰고, 구체 결정은 실제 앱 사례에 근거를 둔다.

### 1.2 정리 — 이 앱의 방향

- **가져온다:** 무채색 바탕·흰 카드, 숫자 두 벌(tabular/proportional), 3상태 의미색, 낮은 행 높이와 접는 섹션, 분류별 월 추이, "할 일로 읽히는" 진단·질문 카드, 해요체.
- **버린다:** 그라데이션 히어로 카드(시간표 앱에는 있었지만 돈 앱에서는 자리만 차지), 큰 화면 제목, 표 줄무늬, 사용자 지정 분류색, 테마 꾸미기, 장식용 일러스트, 게임화, 큰 원형 도넛 하나로 끝나는 대시보드.

## 2. 디자인 원칙

1. **무엇에 썼나가 먼저, 어디서 냈나는 나중.**
   화면의 1차 축은 언제나 *분류*(식비·교육…)이고 카드·계좌는 2차 정보(작은 글씨·흐린 색·뒤쪽 열)다.
   *이유:* 가계 관리의 질문은 "이번 달 뭐가 많았지?"이고 "어느 카드였지?"는 그 다음 질문이다. 카드 기준 화면은 카드 지도 하나로 충분하다.

2. **합계는 혼자 나오지 않는다.**
   총액 옆·아래에는 항상 구성(상위 분류 3~5개 + "그 외")이 같이 보인다. KPI 카드도 숫자 + 구성 막대 한 줄.
   *이유:* 합계만 보면 "많다/적다"만 알 수 있고 무엇을 줄일지 모른다. 구성이 바로 보여야 행동으로 이어진다.

3. **색은 정보다 — 세 종류만, 자리를 나눠서.**
   의미색(초과·여유·중립·안내)은 **숫자·작은 표시**에만, 분류색은 **점·막대·도넛 조각**에만, 나머지는 무채색 잉크.
   *이유:* 시간표 앱에서 검증된 원칙. 돈 앱은 빨강이 곧 "경고"라서, 빨강을 장식에 쓰면 화면 전체가 경고처럼 보인다.

4. **촘촘하게, 그러나 선 하나로 정리.**
   본문 13, 행 높이 40, 위쪽 큰 헤더 없음. 행 구분은 옅은 1px 선(줄무늬 금지), 묶음 구분은 카드.
   *이유:* 사용자 요청(정보 밀도 우선)과 Monarch의 행 높이 축소 사례. 줄무늬는 정보 없이 눈을 끌고, 선 하나가 더 조용하다.

5. **숫자는 읽히는 단위로, 같은 화면에서는 같은 단위로.**
   목록·표는 "만 원" 단위(`23.4만`), 거래 한 건은 원 단위(`12,800원`), 표의 숫자는 tabular 오른쪽 정렬.
   *이유:* `1,234,567`은 자릿수를 세야 읽힌다. 단위를 섞으면 크기 비교가 틀린다.

6. **비교의 기준선은 늘 보인다.**
   실제 값에는 계획(예산)이나 지난 평균이 같이 그려진다 — 막대엔 계획선, 진행 바엔 계획 눈금, 숫자엔 `▲12%`.
   *이유:* "45만"은 기준 없이 판단할 수 없다. 기준선이 있으면 색 없이도 초과가 보인다.

7. **사람이 확인할 일은 큐로 모아 한 번에.**
   글자인식·자동분류가 애매한 것은 화면 곳곳에 흩지 않고 "확인할 것 N개" 큐 하나로. 카드 하나 = 질문 하나 = 탭 한 번.
   *이유:* 가져오기 후 정리가 귀찮으면 데이터가 틀린 채로 쌓인다. 답하기 쉬워야 데이터가 맞는다.

## 3. 색

### 3.1 바탕·글자 (무채색)

시간표 앱보다 살짝 차가운 회색(돈 앱의 단정함). 카드와 바탕은 명도 차로만 나눈다(그림자 없음).

| 토큰 | 라이트 | 다크 | 쓰임 / 대비 |
|---|---|---|---|
| `canvas` | `#F4F5F7` | `#111214` | 화면 바탕 |
| `surface` | `#FFFFFF` | `#1C1D21` | 카드 |
| `surfaceMuted` | `#F7F8FA` | `#24262B` | 카드 안 칸, 입력창, 칩 바탕, 스켈레톤 |
| `ink` | `#191A1D` | `#EDEEF0` | 주 글자·숫자, 선택된 칩/알약 바탕 (카드 대비 17.4 / 14.5:1) |
| `textSub` | `#5B5F67` | `#A8ACB4` | 보조 글자(카드명, 날짜) (6.4 / 7.4:1) |
| `textMuted` | `#6C7078` | `#8A8E96` | 라벨·캡션, 가장 흐린 **글자** 한계 (카드 5.0 / 5.1:1, 바탕 4.6 / 5.7:1) |

| `lineStrong` | `#D5D7DC` | `#3A3D43` | 표 머리 아래 선, 차트 축 기준선(0선) |

`#9AA0A8`(흰 카드 2.6:1) 같은 더 흐린 회색은 **글자에 쓰지 않는다.** 비활성 아이콘·플레이스홀더 점에만.

### 3.2 의미색 — "판단"

색 3개 + 무채색 1개. 각 색은 **mark(점·막대·선) / text(글자) / container(옅은 면)** 한 벌.
`text`는 흰 카드와 container 위 모두 4.5:1 이상.

| 토큰 | 뜻 | 라이트 mark / text / container | 다크 mark=text / container | 쓰는 곳 |
|---|---|---|---|---|
| `over` | 계획 초과, 지난달보다 늘어남(지출), 줄일 것 | `#CC3430` / `#B7191C` (6.6:1) / `#FFEDEB` | `#F66D62` (5.8:1) / `#442320` | 초과 금액 숫자, 진행 바의 넘친 부분, `▲` 증감, 진단 "줄일 것" 배지 |
| `under` | 계획보다 덜 씀, 여유, 줄어듦(지출) | `#1A8A51` / `#00703E` (6.2:1) / `#E5F7EB` | `#4EC983` (8.0:1) / `#173523` | 남은 금액, `▼` 증감, 진단 "여유 있음" 배지 |
| `info` | 안내·처리 중·가져오기 | `#3275B4` / `#1A609E` (6.5:1) / `#E8F3FF` | `#73B0EE` (7.4:1) / `#192F46` | 동기화, 가져오기 진행, 확인 질문 큐 배지 |
| `neutral` | 계획과 같음(±5%), 판단 없음 | `textSub` | `textSub` | 증감 `−`, "계획대로" |

규칙:
- **면을 크게 칠하지 않는다.** container는 배지·확인 질문 카드 한 장 정도에만. 화면 하나에 `over` container가 2개 넘으면 디자인을 다시 본다.
- **색만으로 전하지 않는다.** 항상 기호(`▲▼`)나 글자("초과", "남음")와 같이.
- **증감 색은 "가계에 좋은가"로 정한다.** 지출이 늘면 `over`(빨강), 줄면 `under`(초록). 수입·저축은 반대. 주식 앱의 "상승=빨강" 관습과 다르므로, 증감 표시에는 항상 `▲▼`와 부호를 같이 쓴다.
- **±5% 안은 `neutral`.** 작은 흔들림에 빨강·초록을 켜지 않는다(경고 피로 방지).
- 주의(노랑·주황) 단계는 **두지 않는다.** 계획의 80~100%는 색 없이 진행 바 길이와 "남은 3.2만" 글자로 충분하고, 주황은 식비 분류색 계열과 겹친다.

### 3.3 분류색 — "무엇에"

17개 분류(16 + 기타)를 **6개 색 계열로 묶고, 계열 안에서 농도 3단계**로 나눈다.
비슷한 분류가 비슷한 색이라 17색이 무지개처럼 시끄럽지 않고, 계열만 봐도 "먹는 데 / 집에 / 아이에게"가 읽힌다.
OKLCH로 계열마다 밝기를 같게 맞춰(라이트 mark 0.52 / 0.635 / 0.75) 특정 색만 튀지 않게 했다.
의미색 색상(빨강 27°, 초록 155°)은 피했다 — 분류 막대가 "초과"나 "여유"로 읽히지 않게.

- **3단계 mark(가장 옅은 것)는 흰 카드 대비 2.2~2.4:1**로 그래픽 대비 기준(3:1) 미달이다. 그래서 ① 혼자 쓰는 점·선에는 쓰지 않고, ② 쌓은 막대·도넛에서는 조각 사이 2px 간격 + 바깥 라벨을 붙여 쓴다. 혼자 보여야 하면 같은 계열 1단계 색 + 아이콘으로 구분.
- 분류 순서(1~17)는 고정이다. 범례·필터 칩·쌓은 막대의 위→아래 순서 모두 이 순서(단, "상위 N" 차트는 금액 순).
- 분류가 추가되면 가장 가까운 계열의 빈 단계에 넣고, 계열마다 3개를 넘기지 않는다. 넘치면 분류 체계를 먼저 다시 본다.

### 3.4 구독 분야색 — Ninedogs에서 이어받음

구독 화면(구독 목록·결제 캘린더·구독 통계) 안에서는 가계부 분류가 거의 다 "구독·디지털" 하나라 구분이 안 된다.
그래서 그 안을 다시 나누는 **구독 분야**(Ninedogs `ServiceCategory` 8개 + 기타)를 둔다.

이어받는 원칙(Ninedogs `category_colors.dart`):
- **색은 분야에 고정.** 순위·금액 순으로 색을 주면 다시 열 때마다 같은 분야가 다른 색이 된다.
- **채도·밝기를 맞춰 하나만 튀지 않게.** 쨍한 분야가 실제보다 커 보인다.
- **기타는 무채색.** 색을 주면 실제 분야처럼 보인다.

바꾸는 것: 값을 3.3장과 같은 OKLCH 격자(라이트 밝기 0.60, 다크 0.75)로 다시 뽑고, **영상(빨강)·음악(초록)은 의미색과 겹치지 않게 색상만 옮긴다.**
가계부와 합쳐진 앱에서 빨강 점은 "초과", 초록 점은 "여유"로 읽히기 때문이다. 영상은 빨강과 가까운 장밋빛, 음악은 초록과 가까운 청록이라 사용자의 기억("영상 = 붉은 계열")은 크게 안 깨진다.

자리 나누기(시간표 앱의 "쓰는 자리가 겹치지 않게"):
- **구독 분야색은 구독 화면 안에서만** — 구독 목록의 분야 머리 점, 결제 캘린더 점, 구독 통계 막대.
- 가계부 화면(대시보드·분류별 추이·거래 목록)에서는 구독도 **가계부 분류색**으로 칠한다. 분야 → 분류 대응:
  `mobility` → `transport`(교통·차량), 나머지 7개 + 기타 → `subscription`(구독·디지털). `membership`(쿠팡 멤버십류)은 사용자가 `household` 등으로 바꿀 수 있다.

### 3.5 사람·카드·계좌

- **사람(부부·자녀) 표시**는 색이 아니라 이니셜 원형 배지(`ink` 테두리, 16px)로. 분류색과 경쟁하지 않게.
- **카드·계좌**는 색 없이 아이콘 + 짧은 이름("A카드", "생활비 통장"). 실제 카드사 브랜드색은 쓰지 않는다(브랜드 흉내 금지 + 화면이 카드색 축제가 된다).

| 대상 | 기준 | 이 문서의 값 |
|---|---|---|
| 본문·숫자 글자(13px 이하 포함) | 4.5:1 이상 | `ink` 14.5~17.4, `textSub` 5.9~7.4, `textMuted` 4.6~5.7, 의미색 text 5.6~8.0 |
| 큰 글자(18px w600 이상, KPI 숫자) | 3:1 이상 | 같은 토큰을 쓰므로 자동 충족 |

## 4. 타이포그래피

### 4.1 글꼴

| 용도 | 글꼴 | 이유 |
|---|---|---|
| 한글·영문 전체 | **Pretendard** (SIL OFL, 9굵기 + 가변) | 한글·라틴·숫자가 한 벌로 설계돼 섞여도 기준선·굵기가 맞다. Inter 기반이라 숫자가 단정하다. 무료·상업 사용 가능. |
| 대체 | Noto Sans KR (시스템/번들) | 글꼴 로딩 실패 시 |

시간표 앱은 Noto Sans KR + Poppins(숫자) 조합이었지만, 돈 앱은 숫자와 한글이 한 줄에 계속 섞인다(`식비 23.4만`). 두 글꼴을 섞으면 기준선이 흔들려서 **Pretendard 하나로 통일**한다.
`google_fonts` 패키지에 Pretendard가 없으므로 **앱에 번들**한다(400·500·600·700 네 굵기, 또는 가변 1개).

### 4.2 숫자 — 두 벌

| 숫자 종류 | 설정 | 쓰는 곳 |
|---|---|---|
| **표 숫자** (tabular) | `FontFeature.tabularFigures()` (`tnum`) | 목록·표·거래 행·진행 바 옆 숫자·차트 축 — 세로로 줄 맞춰 비교하는 모든 숫자 |
| **헤드라인 숫자** (proportional) | 기본값 | KPI 큰 숫자 하나, 차트 위 강조 라벨 — 혼자 크게 보이는 숫자 |

- Pretendard의 숫자는 기본이 비례폭이다. `tnum`이 번들한 버전에서 실제로 적용되는지(자릿수 폭이 같아지는지) 첫 구현 때 화면으로 확인한다.
- 단위 글자(`만`, `원`, `%`)는 숫자보다 **한 단계 작고 `textSub`**: `23.4`(13 w600 ink) + `만`(11 w500 textSub). 토스가 기호를 따로 다듬은 것과 같은 이유 — 숫자가 먼저 읽히게.
- 금액 숫자 굵기는 **w600**. 시간표 앱의 "크면 가늘게(w300)"는 버린다. 돈 숫자는 가늘면 불안해 보이고 작은 화면에서 `1`과 `7`이 흐려진다.

### 4.3 크기 스케일 (`AppText`)

시간표 앱과 이름을 맞추되 값은 한 단계씩 작게(어른만 쓰는 정보 밀도 앱). 줄 높이는 한글 기준.

| 토큰 | 크기 | 굵기 | 줄 높이 | 쓰임 |
|---|---|---|---|---|
| `micro` | 10 | 500 | 1.2 | 차트 축 눈금, 막대 안 작은 라벨 |
| `caption` | 11 | 500 | 1.3 | KPI 라벨, 단위(만·원), 보조 설명, 표 머리 |
| `label` | 12 | 600 | 1.3 | 칩, 배지, 탭 |
| `body` | **13** | 400 | 1.45 | 본문 기본, 거래 행 이름 |
| `bodyStrong` | 13 | 600 | 1.45 | 행 안 금액, 강조 본문 |
| `title` | 14 | 700 | 1.35 | 카드 제목, 섹션 머리 |
| `titleLg` | 16 | 700 | 1.3 | 시트·다이얼로그 제목 |
| `numMd` | 18 | 600 | 1.15 | 작은 KPI 숫자, 확인 질문 카드 금액 |
| `kpi` | 22 | 700 | 1.1 | KPI 숫자 |
| `hero` | 26 | 700 | 1.1 | 화면당 한 번: 이번 달 총지출 |

- `display`(32, 대제목)는 **없앤다.** 화면 제목은 앱 바의 `title`(14) 한 줄 — 위쪽 큰 헤더 금지 요청.
- 사용 굵기는 400·500·600·700 네 개만. `FontWeight.bold` 같은 별칭 금지(시간표 앱 규칙 유지).
- 시스템 글씨 크기 확대(1.3배)까지 깨지지 않게: 숫자 칸은 `FittedBox(scaleDown)`이 아니라 단위 축약(`123.4만` → `123만`)으로 줄인다.

### 4.4 금액 표기 규칙 (`MoneyFormat`)

| 상황 | 형식 | 예(가짜) |
|---|---|---|
| 목록·표·차트 라벨(기본) | 만 원 단위, 소수 1자리, 100만 이상은 정수 | `8.4만` · `23.4만` · `184만` |
| 1만 원 미만 | 원 단위 | `8,400원` |
| 1억 이상 | 억 + 만 | `1.2억` |
| KPI 큰 숫자 | 만 단위 정수 + 천 단위 작게 | `184만` `2천원`(작게) 또는 `184.2만` |
| 거래 한 건·확인 질문(정확해야 하는 곳) | 원 단위 전체 | `12,800원` |
| 증감 | 기호 + 퍼센트 + (차액) | `▲12% +8.3만` · `▼4% −1.1만` |
| 환불·수입 | `+` 부호, 지출은 부호 없음 | `+15,000원` |
| 0 / 데이터 없음 | `0원` / `—` | 빈칸으로 두지 않는다 |
| 구독 한 건(목록·캘린더) | 원 단위 전체(청구액이라 정확해야 함) | `13,500원` |
| 연간·주간 결제 구독을 목록에서 비교할 때 | **월 환산** + 숫자 위 `월별` 작은 라벨 (Ninedogs `MonthlyAmountText`). 매월 결제는 라벨 없음 | `월별` `9,917원` |
| 외화 결제 | 원화 환산이 주, 원래 금액은 뒤에 작게 `textSub` (Ninedogs `KrwAmountText`). 환율을 아직 못 받았으면 원래 통화로 | `13,900원` `($9.99)` |

- 반올림은 표시만. 합계는 원 단위로 계산한 뒤 마지막에 줄인다(구성 항목 합이 총액과 1천 원 단위로 안 맞을 수 있다 — 총액 쪽을 정확값으로 두고, 툴팁에 원 단위 표기).
- **같은 표 안에서는 단위를 섞지 않는다.** 한 열이 전부 만 단위면 `8,400원`도 `0.8만`으로.
- 음수 기호는 하이픈(`-`)이 아니라 마이너스(`−`, U+2212) — 숫자 폭이 `+`와 같다.

| `progress` | 6 | 진행 바 두께(목록 안), 큰 것 8 |
| `sparkline` | 20 | 스파크라인 높이 |
| `appBar` | 44 | 앱 바 (기본 56보다 낮게) |

### 5.3 `AppRadius`

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `xs` | 4 | 막대 끝, 진행 바, 작은 배지 |
| `sm` | 8 | 칩, 입력창 |
| `md` | 10 | 버튼, 행 눌림 표시 |
| `lg` | 14 | 카드 기본 |
| `xl` | 20 | 바텀시트 위쪽 |
| `pill` | 999 | 세그먼트 탭, 하단 알약 내비 |

### 5.4 `AppElevation` — 그림자는 거의 없다

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `none` | 없음 | 카드 기본(명도 차로 구분) |
| `floating` | `0 4 16 rgba(17,18,20,0.08)` | 하단 알약 내비, FAB, 드래그 중인 카드 |
| `sheet` | `0 -2 12 rgba(17,18,20,0.06)` | 바텀시트 |

다크 모드는 그림자 대신 한 단계 밝은 바탕(`surfaceMuted`)으로 띄운다.

### 5.5 `AppMotion`

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `fast` | 120ms | 칩 선택, 눌림 |
| `normal` | 200ms | 섹션 접기/펴기, 탭 전환 |
| `chart` | 400ms | 차트 첫 그리기(막대 0→값), 월 바꿀 때 값 보간 |
| `curve` | `Curves.easeOutCubic` | 기본 |
| `curveEmphasis` | `Curves.easeInOutCubicEmphasized` | 시트 열기 |

- 숫자 굴리기(카운트업) 애니메이션은 **하지 않는다.** 돈 숫자가 움직이면 순간 틀린 값이 보인다. 값은 즉시 바뀌고 차트만 보간한다.
- 시스템 "애니메이션 줄이기"가 켜져 있으면(`MediaQuery.disableAnimations`) 모두 0.

### 5.6 `ThemeExtension` 구성 제안

| 클래스 | 내용 |
|---|---|
| `AppPalette extends ThemeExtension<AppPalette>` | `canvas, surface, surfaceMuted, ink, onInk, textSub, textMuted, line, lineStrong` + `semantic` + `categories` |
| `SemanticColors` | `over, under, info, neutral` 각각 `SemanticTone { mark, text, container }` |
| `CategoryPalette` | `Map<SpendCategory, CategoryTone>` + `tone(SpendCategory)` + `others`(그 외 회색) |

| `ChartTheme extends ThemeExtension<ChartTheme>` | 축·눈금·계획선·툴팁 색과 두께(아래 6장) — fl_chart에 넘길 값을 한곳에 |

`context.palette`, `context.chart` 확장 getter로 꺼낸다. 화면 코드에서 `Color(0x…)`·숫자 간격을 직접 쓰지 않는다.

## 6. 차트 스타일 가이드 (fl_chart 기준)

### 6.1 공통

| 항목 | 규칙 |
|---|---|
| 배경 | 투명(카드 위) |
| 테두리 | `FlBorderData(show: false)` |
| 가로 눈금 | 3~4줄, `grid` 색 1px 점선 `[2, 3]`. 세로 눈금 없음 |
| 0선 | `lineStrong` 1px 실선 |
| 축 라벨 | `micro`(10) `textMuted`, tabular. Y축은 **왼쪽에 최대 3개 값**(0·중간·최대, 만 단위), 오른쪽·위쪽 숨김 |
| X축 라벨 | 월: `1월`… 12개가 안 들어가면 홀수 달만. 현재 달은 `ink` w600 |
| 툴팁 | `ink` 바탕 + `onInk` 글자, 라운드 8, `caption`. 내용 순서: 기간 → 금액(원 단위 정확값) → 계획 대비 |
| 터치 | 길게 누름이 아니라 **탭**으로 툴팁, 탭한 막대/점 외에는 40% 투명 |
| 범례 | 차트 아래 한 줄, 점 6px + `caption`. 4개 넘으면 차트 대신 옆 목록이 범례 역할 |
| 빈 값 | 0인 달은 막대 없음 + X축 라벨은 표시. 데이터가 아예 없는 달(가져오기 전)은 라벨 `textMuted` + 빗금 없이 비움 |

### 6.2 막대 — 월별 지출 (`BarChart`)

- 막대 폭: compact 10, medium 14, expanded 18. 라운드 위쪽만 `xs`(4).
- 색: 기본 `ink` 20% 투명도(지난 달들) + **현재 달만 `ink` 100%**. 분류색은 쌓은 막대일 때만.
- **쌓은 막대**(분류 구성): 위→아래가 아니라 **아래부터 금액 큰 순**, 조각 사이 `xxs`(2) 간격(`BarChartRodStackItem` 사이에 바탕색 얇은 조각 대신 `rodStackItems` 경계에 2px 투명 처리), 최대 6조각(상위 5 + 그 외).
- **계획선**: `ExtraLinesData.horizontalLines`에 `HorizontalLine`, `ink` 1.5px 점선 `[4, 3]`, 오른쪽 끝에 라벨 `계획 180만`(`micro`). 막대가 계획선을 넘으면 **넘은 부분만** `over.mark`로 덧칠(막대를 두 조각으로 쌓아 표현).
- 값 라벨: 막대 위에 숫자를 다 쓰지 않는다. 현재 달과 최대 달 두 개만.

### 6.3 선 — 분류별 월 추이 (`LineChart`)

- 선 두께 2, `isCurved: true`, `curveSmoothness: 0.2`(과장 금지), `preventCurveOverShooting: true`.
- 점: 마지막 달만 반지름 3 점 + 오른쪽에 값 라벨. 나머지 점 숨김.
- 여러 분류 비교: 최대 3개 선. 넘으면 작은 그림 여러 장(스파크라인 표)으로.
- 계획/평균: `HorizontalLine` 점선(6.2와 같은 모양). 평균선 라벨은 `평균 23만`.
- 영역 채움(`belowBarData`)은 한 선일 때만, 선 색 12% → 0% 세로 그라데이션.

### 6.4 도넛 — 이번 달 구성 (`PieChart`)

- **가운데 구멍 크게**(`centerSpaceRadius` = 반지름의 62%), 두께 얇게. 가운데에 총액 `numMd` + `이번 달` `caption`.
- 조각 사이 `sectionsSpace: 2`, 시작 위치 12시(`startDegreeOffset: -90`), 큰 순 시계 방향.
- 최대 6조각(상위 5 + 그 외). 조각 위 글자는 쓰지 않고, **오른쪽(또는 아래)에 목록 범례**: 점 · 분류명 · 금액 · 비율 — 이 목록이 본체, 도넛은 그림.
- 도넛은 대시보드에 **하나만**. 비교(이번 달 vs 지난달)는 도넛 두 개가 아니라 막대로.

### 6.5 스파크라인 (`LineChart`, 장식 전부 끔)

- 높이 20, 폭 48~64, 선 1.5, 축·눈금·툴팁·터치 모두 끔.
- 최근 6개월. 색은 `textSub`, 마지막 점만 분류 mark 색 반지름 2.
- 계획선이 있으면 `line` 색 1px 실선.
- 표·목록 행 오른쪽에 숫자와 같이 — 스파크라인만 혼자 두지 않는다.

### 6.6 가로 비교 막대 (fl_chart 아님 — 직접 그림)

"분류별 이번 달" 목록처럼 행마다 들어가는 막대는 fl_chart 대신 `ProgressBar`(7.4) 컴포넌트를 재사용한다. 차트 위젯을 행마다 만들면 무겁고 정렬이 어긋난다.

### 6.7 라벨 규칙 요약

1. 숫자 라벨은 만 단위, tabular, `micro`/`caption`.
2. 한 차트에 숫자 라벨 최대 3개(현재·최대·계획). 나머지는 탭해서 툴팁.
3. 축 제목(`(만 원)`)은 쓰지 않는다 — 라벨에 `만`이 붙어 있다.
4. 범례 순서 = 차트 순서 = 금액 순.
5. 색이 6개를 넘으면 차트를 바꾼다(작은 그림 여러 장 / 표).

### 7.2 KPI 카드 (`KpiTile`, `KpiStrip`)

- 구성(위→아래): 라벨(`caption` textMuted) → 숫자(`kpi` 22 w700, 단위 `caption`) → 비교 한 줄(`▲12% +8.3만 · 지난달` `caption`, 의미색) → **구성 막대 한 줄**(높이 6, 상위 4분류 + 그 외 쌓은 막대, 아래 점·이름 2~3개 `micro`).
- 크기: compact에서 2개가 한 줄(`KpiStrip`), 높이 약 96. 구성 막대를 숨기는 옵션은 두지 않는다(원칙 2).
- 대시보드 첫 줄 예(가짜): `이번 달 지출 184만 ▲6%` / `고정 92만` / `변동 92만 · 계획의 71%`.
- 숫자를 탭하면 해당 분해 화면으로.

### 7.3 분류 칩 (`CategoryChip`, `FilterChipBar`)

- 높이 28, 라운드 `sm`, 좌우 10. 왼쪽 점(6px, 분류 mark) + 이름(`label`).
- 상태: 꺼짐 = `surfaceMuted` 바탕 + `textSub` 글자 / **켜짐 = `ink` 바탕 + `onInk` 글자 + 점 유지** / 눌림 = 투명도 0.8.
- `FilterChipBar`: 가로 스크롤 한 줄, 맨 앞 `전체`. 여러 개 선택 가능(슬라이서). 선택된 칩은 앞으로 모으지 않는다(위치가 바뀌면 다시 찾게 된다).
- 칩 묶음 종류: 분류 / 결제수단(카드·계좌, 점 없음) / 주기(매월·매년) / 사람. 같은 줄에 섞지 않고 종류마다 줄을 나누거나 `필터` 시트로.
- 선택 결과 요약은 칩 줄 바로 아래 `caption`: `3개 선택 · 12건 · 월 47.3만`.

### 7.4 진행 바 — 예산 대비 (`BudgetBar`)

- 두께 6(목록) / 8(카드 머리), 라운드 `xs`, 바탕 `surfaceMuted`.
- 채움: **쓴 금액 = 분류 mark 색**(목록에서 무엇인지 보이게). 단일 분류가 아닌 합계 바는 `ink`.
- 계획 눈금: 바 위 세로 2px `ink` 선(계획이 바 끝이 아닐 때 — 바의 끝을 "계획의 120%"로 두어 초과분이 보이게).
- **초과**: 계획 눈금 오른쪽 부분만 `over.mark`. 바 옆 글자 `3.2만 초과`(`over.text`).
- 여유: 색 바꾸지 않음. 글자 `남은 12만`(`textSub`), 이번 달 진행률보다 많이 남았으면(예: 월 60% 지났는데 30%만 씀) `under.text`.
- 오른쪽 숫자 열: `쓴 금액 / 계획` tabular, `23.4만 / 30만`.
- 진행 바만 있고 숫자가 없는 형태는 금지(YNAB처럼 숫자의 보조).

### 7.5 거래 행 (`TransactionRow`)

- 높이 40(한 줄) / 52(두 줄). 아래 1px `line`(마지막 행은 없음). **줄무늬 금지.**
- 열: [분류 점 6] · [이름 `body` — 한 줄 말줄임] · [보조줄: 카드명·날짜 `caption` textSub, 두 줄일 때만] · [금액 `bodyStrong` tabular 오른쪽 정렬, 원 단위].
- 카드·계좌는 **보조줄 또는 생략**(원칙 1). 카드별 보기 필터일 때만 앞으로.
- 상태 표시: 미확인(확인 질문 큐에 있음) = 이름 앞 `info` 점 + 행 끝 `?` 아이콘 / 고정지출 = 작은 `반복` 아이콘 / 환불 = 금액 `+` + `under.text`.
- 날짜 묶음 머리: `11.18 (화)` `caption` textMuted + 오른쪽 그날 합계, 높이 28, 선 없음.
- 밀기 동작: 왼쪽으로 밀면 분류 바꾸기, 오른쪽은 없음(실수 방지).

### 7.6 분류별 추이 표 (`CategoryTrendTable`)

핵심 화면 "항목별 월 추이"의 표.
- 행 높이 36, 첫 열 고정(점 + 분류명), 이후 월 열(만 단위, tabular, 오른쪽 정렬), 마지막 열 스파크라인 + 평균 대비 `▲▼`.
- 머리 아래 `lineStrong`, 행 사이 `line`. 현재 달 열만 `ink` w600, 지난 달들 `textSub` 400.
- 계획 초과 칸: 숫자만 `over.text`(칸 배경 칠하지 않음). 합계 행은 맨 위(합계가 아래에 있으면 스크롤해야 보인다), `surfaceMuted` 바탕 1행만 허용 — 이것은 줄무늬가 아니라 머리다.
- 행 탭 → 그 분류의 거래 목록.

### 7.7 진단 카드 (`InsightCard`) — 줄일 것 / 여유 있는 것

- 두 묶음을 나란히(medium 이상) 또는 위아래. 머리 배지: `줄일 것` (`over` container + text) / `여유 있음` (`under`).
- 각 줄: 분류 점 · 분류명 · `계획보다 8.2만 많아요` / `평균보다 5만 적어요` · 작은 스파크라인. 최대 3줄 + `더 보기`.
- 근거를 한 줄 붙인다: `최근 3개월 평균 31만, 이번 달 39만`. 근거 없는 판단 문구 금지.

### 7.8 카드-통장 연결 카드 (`FundingMapCard`, `FundingNode`)

"어떤 카드에 어떤 정기결제가 붙어 있고, 그 카드 대금이 어느 통장에서 빠지나."
- 세 칸 흐름: **[정기결제들] → [카드] → [출금 통장]**. compact는 위→아래 세로 흐름(통장이 맨 위 묶음, 그 아래 카드, 그 아래 결제 목록 — 접기), expanded는 왼→오 3열.
- `FundingNode`(통장·카드): 높이 44, `surfaceMuted` 바탕, 라운드 `md`, 아이콘 + 짧은 이름(`bodyStrong`) + 오른쪽 월 합계(tabular) + 결제일/출금일 `caption`(`매월 14일`).
- 연결선: `lineStrong` 1.5px, 직각 꺾임(곡선 아님), 노드 사이 간격 `md`. 선택한 노드의 경로만 `ink`, 나머지 `line`으로 흐리게.
- 정기결제 줄은 분류 점 + 이름 + 금액 — **분류가 먼저 보이게**. 예(가짜): `● 영상 구독 1.7만`, `● 통신 6.5만`.
- 경고: 출금 통장 예상 잔액 부족은 노드 오른쪽 `over` 배지 `2.3만 부족`, 카드가 해지·만료 예정이면 `info` 배지.
- 실제 카드 이미지·카드사 로고 쓰지 않는다.

### 7.9 고정지출 목록 (`RecurringList`)

- 위: `FilterChipBar` 두 줄(분류 / 결제수단) + 정렬(금액순·결제일순) 세그먼트.
- 행: `TransactionRow` 두 줄 형태 + 결제일 `매월 25일` + 다음 결제까지 `D-3`(3일 이내면 `info.text`).
- 맨 위 요약: `12건 · 월 92만 · 연 1,104만` — 필터를 바꾸면 이 줄이 바뀐다.

### 7.10 확인 질문 카드 (`ReviewQuestionCard`, `ReviewQueue`)

가져오기(뱅크샐러드 엑셀·쿠팡 캡처 글자인식) 후 사람이 답할 것.
- 카드 한 장 = 질문 하나. `surface`, 왼쪽 3px `info` 띠, 라운드 `lg`.
- 위: 출처 배지(`엑셀` / `캡처`) + 진행 `3 / 12`(`caption`).
- 본문: 원본 그대로 한 줄(`caption` textMuted, 예: `쿠팡 11.18 12,800원`) → 질문(`body` w600: `이 결제는 어떤 분류예요?`) → **답 버튼 2~4개**(분류 칩 모양, 높이 36, 추천 답이 첫 번째 + `추천` 작은 표시) → `다른 분류…` · `나중에`.
- 글자인식 결과가 의심스러우면 금액·날짜 옆 `확인 필요` 밑줄(점선 `info`) + 탭하면 수정. 캡처 원본 썸네일(40×40)은 오른쪽.
- 답하면 카드가 위로 밀려나고 다음 카드(`normal` 200ms). 맨 끝: `다 확인했어요 · 12건 정리됨`.
- 큐 입구: 대시보드 맨 위 띠 `확인할 것 12개 ›`(`info` container). 0개면 띠가 사라진다(빈 띠를 두지 않는다).

### 7.11 빈 상태 (`EmptyState`)

- 카드 안에서 작게: 아이콘 24(`textMuted`) + 한 줄 이유(`body`) + 다음 행동 버튼 하나. 높이 120 안팎. 큰 일러스트 금지.
- 예: `이번 달 거래가 아직 없어요` + [엑셀 가져오기] / `고정지출을 찾지 못했어요` + [직접 추가].
- 필터 결과 0건: `조건에 맞는 항목이 없어요` + [필터 지우기].

### 7.12 스켈레톤 (`Skeleton`, `SkeletonRow`, `SkeletonKpi`)

- 실제 레이아웃과 **같은 크기·같은 위치**(행 40, 숫자 칸 폭 고정)로 회색 막대(`surfaceMuted`, 라운드 `xs`). 레이아웃이 데이터 도착 후 흔들리지 않게.
- 반짝임(shimmer)은 1.2초 주기 아주 옅게(투명도 0.5↔1). 애니메이션 줄이기 설정이면 정지.
- 300ms 안에 오는 데이터에는 스켈레톤을 띄우지 않는다(깜빡임 방지). Firebase 캐시가 있으면 캐시 먼저 + 위쪽 얇은 `info` 진행 선.

### 7.14 서비스 아이콘 (`ServiceIcon`) — Ninedogs 그대로

구독 서비스가 나오는 모든 곳의 아이콘. **Ninedogs `widgets/service_icon.dart`의 그리는 방식을 바꾸지 않고 옮긴다.**
사용자가 가장 마음에 들어 한 부분이고, 아이콘 출처별로 실제 문제를 겪으며 다듬어진 결과다.

- 모양: 원(기본) 또는 모서리 둥근 사각형(지름의 26%). 테두리선·그림자 없음.
- 그리는 방식(출처에 따라 다르다):
  - **App Store 아트워크**(배경이 네 변까지 찬 정사각형): 원에 꽉 채워(`cover`) 자르고 **1.06배 살짝 키워** 아트워크 둘레의 얇은 회색 실선을 원 밖으로 밀어낸다.
  - **파비콘**(배경 없음·로고가 가장자리까지 참): 두 겹. 뒤 겹 = 같은 이미지를 꽉 채워 흐리게(`blur` σ = 지름 × 0.08) — 링 부분이 아이콘 자기 색으로 이어진다. 앞 겹 = 원본을 **지름의 70%**(정사각형이 원에 들어가는 한계 1/√2 ≈ 70.7%에서 조금 줄임) `contain`으로 얹어 한 조각도 잘리지 않는다.
  - **받는 중**: 아이콘 **가장자리 픽셀 평균색**(없으면 카탈로그 브랜드색)으로 원을 채워 둔다 — 이미지가 들어와도 색이 튀지 않는다.
  - **못 받음**: 첫 글자 모노그램(지름 × 0.38, w700). 글자색은 바탕 밝기로 검정/흰색.
  - 출처 순서: App Store 검색(512px) → 도메인 파비콘 → 첫 글자.
- 크기 토큰 `AppSize.icon*`:

| 토큰 | 지름 | 쓰는 곳 |
|---|---|---|
| `iconXs` | 18 | 거래 행에서 분류 점 대신(구독으로 매칭된 거래), 캘린더 날짜 칸 안(expanded) |
| `iconSm` | 28 | 구독 목록 행, 카드 지도의 정기결제 줄, 확인 질문 카드 |
| `iconMd` | 40 | 구독 상세 머리, 결제 캘린더 날짜 시트 |
| `iconLg` | 56 | 서비스 고르기 그리드(온보딩·추가) |

- 18px에서는 흐림 반경이 1.4px뿐이라 파비콘 링이 거의 없다 — 그대로 둬도 된다(실제 기기에서 확인).
- 아이콘은 **분류 점을 대신**할 수 있지만 분류 정보를 지우지는 않는다: 구독 목록은 분야 머리로, 거래 행은 보조줄의 분류명으로 남긴다.
- 서비스 아이콘은 브랜드 그림이라 이 문서의 색 규칙 밖이다. 그래서 **아이콘 옆에 브랜드색을 다시 쓰지 않는다**(배지·글자·막대 모두 시스템 색).

### 7.15 구독 목록 (`SubscriptionList`, `SubscriptionRow`, `IndexChipBar`)

- 맨 위 요약 한 줄(큰 헤더 없음): `구독 14개 · 월 18.6만 · 연 223만` + 오른쪽 `이번 달 남은 결제 5건 7.2만`.
- 그 아래 **분야 목차 칩** `IndexChipBar` (Ninedogs 원칙: *필터가 아니라 목차*). 누르면 그 분야 구간으로 스크롤만 하고 다른 분야는 남는다. 스크롤하면 현재 분야가 칩에 표시된다.
  - 필터 칩(7.3)과 모양으로 구분: **목차 칩은 채우지 않는다.** 꺼짐 = 투명 바탕 + `textSub`, 현재 = `ink` 글자 w600 + 아래 2px `ink` 막대. 필터 칩의 "켜짐 = 검은 알약"과 섞이지 않게.
  - 칩 왼쪽에 분야색 점, 오른쪽에 그 분야 월 합계(`micro`): `● 영상 4.2만`.
- 분야 머리: 높이 28, 분야색 점 + 분야명(`caption` w600) + 오른쪽 분야 월 합계·개수. 선 없음.
- `SubscriptionRow` (두 줄, 높이 52, 아래 `line`):
  [`ServiceIcon` 28] · [이름 `body` w600 / 보조줄 `caption` textSub: `매월 14일 · A카드` 또는 `매년 3.2 · 만료 2027.3.1`] · [오른쪽: 금액(`MonthlyAmountText` 규칙) + 아래 다음 결제 `D-3`].
  - `D-3` 이내 = `info.text`, 결제일 지났는데 매칭 거래 없음 = `info` `결제 확인 안 됨`, 가격이 오른 지 30일 안 = 금액 옆 `▲` `over.text`.
  - 해지 예정(이용 권한 만료일 있음) = 행 전체 `textSub`로 흐리게 + `만료 3.1` 배지. 해지된 구독은 목록 맨 아래 접힌 `해지한 구독 3` 묶음.
- 기본 정렬은 **월 부담액 큰 순**(무엇에 많이 쓰나가 먼저 — 원칙 1). 정렬 바꾸기: 금액 / 다음 결제일 / 이름.
- 누적 지출(Ninedogs 요구사항)은 상세 화면 머리 KPI: `지금까지 31.2만 · 23개월` + 가격 이력 계단 그래프(`LineChart` `isStepLineChart: true`).
- 계정 정보(아이디·비밀번호 금고)는 상세 화면 안 별도 묶음, 자물쇠 아이콘 + `잠김` 글자. 색 없음.

### 7.16 결제 캘린더 (`PaymentCalendar`)

Ninedogs 캘린더를 이어받는다: "이번 달 언제 얼마씩 빠지는지"와 결제가 몰린 주를 한눈에.

- 월 격자: 일요일 시작, 칸은 **정사각형에 가깝게**(Ninedogs에서 세로로 긴 칸이 화면 절반을 먹었던 문제를 고친 비율). 칸 안: 날짜(`caption`, tabular) + 아래 점.
- 점: 그날 결제되는 구독의 **분야색 점 최대 3개**, 4개 이상이면 세 번째 점을 회색(`etc`)으로 — "더 있음". 점 지름 5, 간격 2.
- **카드 대금 출금일**(카드 지도와 연결): 날짜 숫자 둘레 `ink` 1px 원. 구독 점과 다른 표시라 섞이지 않는다. 탭하면 `A카드 대금 · 생활비 통장 · 예상 84만`.
- 그날 합계: medium 이상에서만 칸 아래 `micro` `textSub` `2.3만`. compact에서는 생략(칸이 좁다).
- 오늘 = 날짜 숫자 `ink` 바탕 원 + `onInk` 글자. 고른 날 = `surfaceMuted` 칸 바탕.
- 격자 위 한 줄: `◀ 11월 ▶` + `이번 달 18.6만 · 남은 결제 7.2만`. 외화 구독도 환율로 환산해 합친다(Ninedogs에서 외화가 합계에서 빠지던 버그를 고친 규칙).
- 격자 아래 목록:
  - 날짜를 안 골랐으면 이 달 결제 전체를 날짜순 — **날짜를 행 안 작은 배지**(`14일`, 폭 고정·줄바꿈 금지)로 넣어 한 줄씩만 차지(Ninedogs에서 날짜 제목 줄 때문에 목록이 두 배로 길어진 문제를 고친 방식).
  - 날짜를 골랐으면 그날 결제만 + 머리 `11.14 (금) · 3건 2.3만`.
- 폴드 expanded: 왼쪽 격자 / 오른쪽 목록 2분할, 칸 안에 `ServiceIcon` 18을 최대 2개까지 점 대신 보여 준다.

### 7.17 거래 ↔ 구독 매칭 표시 (`SubscriptionMatchBadge`)

카드 거래(뱅크샐러드 가져오기)와 등록된 구독을 이어 주는 표시. 가계부와 구독 앱이 합쳐진 이유가 여기에 있다.

| 상태 | 거래 행에서 | 구독 행에서 | 사용자 할 일 |
|---|---|---|---|
| **매칭됨** | 분류 점 자리에 `ServiceIcon` 18 + 보조줄 `구독 · 영상` | 다음 결제 아래 `11.14 결제됨` `textSub` | 없음 |
| **매칭 추정** (금액·날짜·가맹점명이 비슷) | 분류 점 + 행 끝 `info` 점선 고리 아이콘 | — | 확인 질문 큐로: `이 결제가 '영상 구독 A'예요?` [맞아요] [아니에요] |
| **금액이 다름** | 금액 옆 `info` `구독 13,500원과 달라요` | 금액 옆 `▲` | 확인 질문(Ninedogs의 구분을 그대로): [요금이 올랐어요 — 이력 추가] [원래 잘못 적었어요 — 고치기] [이번만 달라요] |
| **결제 안 보임** (결제일 + 3일 지나도 매칭 거래 없음) | — | `info` `결제 확인 안 됨` | 가져오기를 안 했거나 해지됨: [해지했어요] [다른 카드로 냈어요] [기다리기] |
| **해지했는데 결제됨** | 금액 `over.text` + `해지한 구독` 배지(`over` container) | 해지 묶음에서 `over` 배지 | [환불 요청 메모] [다시 구독 중으로] |
| **구독 같은데 등록 안 됨** (같은 가맹점이 3개월 연속 비슷한 금액) | 행 끝 `info` `+` | — | 확인 질문: `매달 나가는 'B 서비스'를 구독에 추가할까요?` [추가] [아니에요] |

- 매칭선은 따로 그리지 않는다. **같은 서비스 아이콘이 거래 행과 구독 행에 똑같이 나오는 것**이 연결 표시다.
- 매칭 관련 질문도 확인 질문 큐(7.10) 하나로 모은다. 질문 카드 왼쪽에 `ServiceIcon` 28, 원본 거래 한 줄은 그 아래.
- 자동 매칭은 확신이 높을 때만 "매칭됨"으로, 나머지는 전부 질문으로. 틀린 자동 매칭이 누적 지출을 망친다.

### 7.18 서비스 고르기 그리드 (`ServicePickerGrid`) + 온보딩

Ninedogs `ServiceBrowser`와 스포티파이식 온보딩을 이어받는다. "클릭 몇 번으로 기록이 끝나는" 경험이 핵심.

- 그리드: compact **4열 고정**, 칸 비율 0.68(아이콘 56 + 이름 두 줄). medium 6열, expanded 8열.
  (Ninedogs는 그리드가 지연 생성이라 분야 위치를 4열 고정 비율로 직접 계산한다 — 열 수가 바뀌면 그 계산도 열 수를 받게 고친다.)
- 위: 검색창 + 분야 목차 칩(`IndexChipBar`). 검색 중에는 분야 구분 없이 결과만.
- 칸 상태:
  - 기본: `ServiceIcon` 56 + 이름(`caption`, 두 줄 말줄임).
  - **선택**: 아이콘 둘레 2.5px 링 + 오른쪽 위 체크 배지. 링 두께만큼 자리를 늘 비워 둬서 선택할 때 크기가 튀지 않는다(Ninedogs 그대로). **색만 바꾼다: 넷플릭스 레드 → `ink`**(빨강은 이 앱에서 "초과").
  - **이미 구독 중**: 아이콘 40% 투명 + 아래 `구독 중` 작은 알약(`textSub` 바탕). 막지는 않는다(요금제가 다른 두 계정).
- 위쪽 `SelectedStrip`: 고른 서비스가 작은 아이콘(28)으로 늘어서는 띠. 하나도 없으면 자리 차지 없음, 고르는 순간 펼쳐짐(`normal`). 띠의 아이콘을 누르면 선택 해제.
- 온보딩 흐름(합쳐진 앱):
  1. **소개** — 한 화면, 아이콘 42 + 제목 + 한 줄 설명 3개(`무엇에 썼는지 한눈에` / `매달 나가는 돈 정리` / `부부가 같이 보기`). 아이콘 바탕은 `ink` 8% 투명(예전 빨강 14% 대신). [시작하기].
  2. **구독 고르기** — 그리드에서 탭. 아래 고정 버튼 `14개 고름 · 다음`.
  3. **요금제·시작일 확인** — 고른 것들만, 전부 기본값이 채워져 있어 그대로 [완료]해도 쓸 만한 데이터가 남는다. 상위 상품에 포함돼 0원으로 맞춘 것은 아래 안내.
  4. (선택) **지출 내역 가져오기** — [뱅크샐러드 엑셀 가져오기] [나중에]. 가져오면 7.17의 매칭이 바로 돈다.
- 카탈로그 기본 가격은 참고값이다. 확인 단계에서 늘 고칠 수 있게 보여 주고, 사실처럼 굵게 강조하지 않는다(`textSub`).

## 8. 폴드(펼침 화면) 대응 레이아웃 그리드

기기: 플립(겉화면 작음, 펼침 세로 좁고 김) · 폴드(겉화면 좁음, 펼침 거의 정사각) · 일반 갤럭시.
폭 구간은 시간표 앱 `Breakpoint` 그대로.

| 구간 | 폭(dp) | 기기 예 | 열 | 좌우 여백 | 열 간격 | 내비 | 화면 구성 |
|---|---|---|---|---|---|---|---|
| `compact` | < 600 | 플립·폴드 겉화면·일반폰 | 4 | 16 | 8 | 하단 알약 | 한 열. KPI 2개씩 한 줄 |
| `medium` | 600–839 | 폴드 펼침 세로, 작은 태블릿 | 8 | 20 | 12 | 하단 알약 | 카드 2열. 목록 + 요약 나란히 |
| `expanded` | ≥ 840 | 폴드 펼침 가로 | 12 | 24 | 16 | 왼쪽 레일(폭 72) | **목록–상세 2분할**(5 : 7) 또는 카드 3열 |

화면별 배치:

| 화면 | compact | medium / expanded |
|---|---|---|
| 대시보드 | KPI → 확인 띠 → 도넛+범례 → 진단 → 월 막대 | KPI 4개 한 줄 → [도넛+범례 \| 월 막대] → [진단: 줄일 것 \| 여유] |
| 분류별 추이 | 표(최근 4개월 + 스파크라인) | 표(최근 12개월 전부) + 오른쪽 선택 분류 선 차트 |
| 거래 목록 | 목록, 탭하면 새 화면 | 왼쪽 목록 / 오른쪽 상세(분류 바꾸기·메모) |
| 카드 지도 | 세로 흐름(통장 → 카드 → 결제) | 가로 3열 흐름 |
| 고정지출 | 칩 2줄 + 목록 | 왼쪽 필터 패널(세로 칩) + 오른쪽 목록 |
| 구독 목록 | 목차 칩 + 분야별 목록 | 왼쪽 목록 / 오른쪽 구독 상세(누적 지출·가격 이력·결제 기록) |
| 결제 캘린더 | 격자 위, 목록 아래 | 왼쪽 격자(칸에 아이콘 18) / 오른쪽 날짜 목록 |
| 서비스 고르기 | 4열 | 6열(medium) / 8열(expanded) |
| 확인 질문 큐 | 카드 한 장씩 | 왼쪽 남은 질문 목록 / 오른쪽 현재 카드 + 원본 캡처 크게 |

규칙:
- **경첩 피하기:** `MediaQuery.displayFeatures`에 경첩/접힘(`DisplayFeatureType.hinge`·`fold`)이 세로로 있으면 2분할 경계를 그 위치에 맞춘다. 반 접힘(테이블탑, 가로 경첩)일 때는 위쪽에 차트, 아래쪽에 목록.
- 펼쳤다 접어도 **선택 상태 유지**(보던 월·필터·선택 거래). 폭이 바뀌면 상세 화면을 목록–상세 중 어느 쪽으로 보일지만 바꾼다.
- 넓은 화면에서 카드가 끝까지 늘어나지 않게 본문 최대 폭 1200. 표는 열이 늘어나는 것(12개월)이지 칸이 넓어지는 것이 아니다.
- 폭 분기는 반드시 `Breakpoint.of(context)`(숫자 600을 화면마다 쓰지 않는다 — 시간표 앱 규칙).

## 9. 카피 톤

| 규칙 | 좋은 예 | 피할 예 |
|---|---|---|
| **숫자 먼저, 해요체, 짧게** | `식비 8.2만 초과` | `식비 항목에서 예산을 초과하셨습니다` |
| 비교는 기준을 같이 | `지난달보다 12% 많아요` | `지출이 많아요` |
| 판단엔 근거 한 줄 | `3개월 평균 31만 → 이번 달 39만` | `과소비 주의!` |
| 감정·꾸중·칭찬 과장 금지 | `계획보다 5만 적게 썼어요` | `대단해요! 🎉 절약왕!` |
| 질문은 답할 수 있게 | `이 결제는 어떤 분류예요?` + 보기 | `분류를 확인해 주세요` |
| 오류는 할 일을 | `엑셀 첫 줄이 달라요. 뱅크샐러드에서 '전체 내역'으로 다시 내보내 주세요` | `파일 형식 오류` |
| 쉬운 말 먼저 | `카드값 빠지는 통장`, `매달 나가는 돈` | `결제 계좌`, `정기 출금 항목` |
| 버튼은 동사 | `가져오기`, `분류 바꾸기`, `나중에` | `확인`, `다음` (뜻이 분명할 때만) |

- 금액은 문장 안에서도 `MoneyFormat`(만 단위). `팔만 이천원` 같은 한글 숫자 금지.
- 사람을 탓하는 주어 금지(`남편이 많이 썼어요` ✕). 누가 썼는지는 필터·배지로만 보여 준다 — 부부가 같이 보는 앱이다.
- 느낌표·이모지는 쓰지 않는다. 확인 큐를 다 끝냈을 때 한 번 정도 `다 확인했어요`.
